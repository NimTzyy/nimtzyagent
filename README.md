# NimTzyAgent

A mobile client for the DeepSeek API. Android and iOS, no backend: requests go
from the device to `https://api.deepseek.com` with your own key.

- Platform targets: **Android 16+ (API 36)**, **iOS 26.0+**, **arm64 only**.
- Built with Expo SDK 57, React Native 0.86, React 19, TypeScript (strict), Expo Router.
- Streaming responses, thinking mode with a collapsible reasoning block,
  image and text-file attachments, on-device SQLite history, per-message token
  and cost estimates.
- System prompts live in Settings: a default prompt for new chats, plus named
  presets for reuse.
- **Web research:** the model can call `search_web` and answer from the results.
- **Agent file mode:** the model can create folders and write files inside a
  folder you pick — and it is told to write projects *into* the folder rather
  than print them into the chat — and an HTML block it writes can be opened in a
  sandboxed preview. Settings has a **Test folder** action that runs the real
  write path against your folder and reports the device's own words where it
  stops. The chat says so when the tools are on without a folder, since the
  switch alone does nothing.

## Getting it running

```bash
npm install
npm start          # Metro; press a for Android, i for iOS
```

The keyboard handling and the HTML preview use native modules
(`react-native-keyboard-controller`, `react-native-webview`) that are not part of
the Expo Go client, so use the built APK, an iOS build, or a development build
(`npx expo run:android`, `npx expo run:ios`) rather than Expo Go.

The first launch asks for an API key. Create one in the DeepSeek console.
The key is validated against the API before it is stored, and it is written to
the device keychain (Keychain on iOS, Keystore on Android) via `expo-secure-store`.
It is never logged, never written to SQLite or AsyncStorage, and never bundled.

The permissions match the features and nothing else: network access and network
state, the camera and photo library for attachments, and vibration for the send
haptic. The debug-only overlay permission the Expo template declares is stripped
through `android.blockedPermissions`, and `expo-secure-store` excludes the key
from Android backup and device-to-device transfer.

## Building

### Android APK, locally

Requires JDK 17 and an Android SDK with platform 36 and build-tools 36.0.0.

```bash
./tools/build-android.sh
# -> dist/nimtzyagent-1.1.4-arm64.apk   (also under android/app/build/outputs/apk/release/)
```

The script prints the SHA-256 of the APK. It keeps a copy in `dist/` because
`android/` is generated by `expo prebuild` and a later run will wipe it.

The script runs `expo prebuild`, then Gradle with `reactNativeArchitectures=arm64-v8a`.
Signing is wired up by `tools/plugins/with-release-signing.js`, which reads
`NIMTZY_STORE_FILE`, `NIMTZY_STORE_PASSWORD`, `NIMTZY_KEY_ALIAS`, and
`NIMTZY_KEY_PASSWORD` from Gradle properties.

A keystore is committed-ready but **not** committed:

```bash
keytool -genkeypair -v -keystore nimtzy-release.keystore -alias nimtzy \
  -keyalg RSA -keysize 4096 -validity 10950
```

The development keystore at `./nimtzy-release.keystore` uses the password
`nimtzyagent`. Generate your own before distributing anything, and keep it out
of version control — losing it means losing the ability to update the app.

### iOS IPA

iOS cannot be built here, or on any Linux machine: the compiler is Xcode and
Apple ships it for macOS only. There is no open-source substitute. Every route
below therefore borrows a Mac — either GitHub's or Expo's.

**via GitHub Actions, no Apple account (what `.github/workflows/ios.yml` does).**
The workflow runs on a `macos-26` runner, prebuilds the project, installs pods,
and asks `xcodebuild` for a device build with `CODE_SIGNING_ALLOWED=NO`. The
result is an **unsigned** `arm64` IPA, uploaded as a build artifact.

Unsigned means exactly what it says: the device will not install it as-is.
Sideloadly or AltStore re-sign it with a free Apple ID on the way in. What that
costs you: the signature expires after **7 days**, you can hold 3 sideloaded
apps at a time, and Developer Mode has to be on (Settings → Privacy & Security)
on iOS 16 and later. AltStore needs AltServer running on a computer; Sideloadly
is a desktop app for Windows or macOS. There is no way to install it with the
phone alone.

The workflow also checks the artifact before uploading it — that `main.jsbundle`
is present and not truncated, that the binary is arm64, and that the
`MinimumOSVersion` is what `app.json` asked for. A build that produces an IPA
with no JS bundle installs perfectly and then shows a white screen, which is a
worse outcome than a failed build, so that case fails the job instead.

A `verify` job runs typecheck, tests and lint on Linux first, so a broken commit
never reaches the macOS queue. Note that macOS runner minutes bill at 10x:
a private repo gets 2000 minutes a month, which is roughly 200 macOS minutes,
or about ten of these builds. A public repo has no metered limit.

**via EAS Build, with an Apple Developer account ($99/year).** Produces a
*signed* `.ipa` that installs without a desktop tool and does not expire:

```bash
npm i -g eas-cli
eas login
eas init                                           # link the project to your account
eas build --platform ios --profile preview         # ad-hoc IPA, up to 100 devices
eas build --platform android --profile production  # AAB for Play
```

This is the only route to an IPA that installs on a phone unaided. Ad-hoc
distribution needs each device's UDID registered (`eas device:create`) before
the build. Without the paid membership, EAS can only produce a **simulator**
build, which is a `.app` in a tarball — not an IPA, and not installable on an
iPhone.

Profiles live in `eas.json`; every one of them pins `arm64-v8a` for Android and
excludes the simulator for iOS.

Both routes need the same thing from `app.json`: `ios.deploymentTarget` is
`26.0`, so the toolchain must have the iOS 26 SDK — Xcode 26 or newer. The
workflow selects the newest installed Xcode 26 explicitly and prints it, rather
than trusting whatever the image happens to default to that week. That setting
also means the app installs on iOS 26 and later only; lower it if you want
older iPhones to be able to run it.

## Configuration

`app.json` holds everything the native build needs:

| Setting | Value |
| --- | --- |
| Android package / iOS bundle id | `com.nimtzy.agent` |
| `android.minSdkVersion` | 36 (Android 16) |
| `android.targetSdkVersion` | 36 |
| `ios.deploymentTarget` | 26.0 |
| Architectures | arm64-v8a (Android), arm64 / arm64e (iOS) |

Edge-to-edge is mandatory on Android 16, so the app draws its own headers and
honours safe-area insets throughout. There is no `edgeToEdgeEnabled` flag to set.

## Layout

```
src/core/      API client, SSE parser, model registry, pricing, request building,
               tool definitions and dispatch, search providers
src/db/        SQLite schema and repositories (conversations, messages, presets)
src/state/     zustand stores: settings (preferences + key) and the chat session
src/ui/        theme, components, markdown and code rendering
src/app/       Expo Router screens
src/lib/       workspace (SAF folder access), html block extraction, strings
tools/         asset generator, Android build script, config plugins
```

Notes on the parts that carry the most weight:

- `src/core/sse.ts` parses event streams incrementally, because network chunks
  split at arbitrary offsets — including in the middle of a blank-line boundary.
- `src/core/stream.ts` is the only place that knows the wire field names. If
  DeepSeek renames a field, that file is the whole fix.
- `src/core/round.ts` folds one streamed round into a draft, and holds the two
  rules for reading it that the streaming code cannot check by eye. A `[DONE]`
  sentinel names no finish reason, and because it arrives in the same read as
  the last real chunk, treating it as authoritative erases the reason just
  given — an erased `tool_calls` silently skips the tool and leaves the user a
  step chip with no answer after it. And a round is a tool round when the API
  said so *or* when every call's arguments parse, since a stream can stop
  between the arguments and the reason. Both are pinned by
  `src/core/__tests__/round.test.ts`, which folds real decodes of the wire
  format rather than hand-built events.
- `src/core/models.ts` is the only place that knows model IDs. DeepSeek retires
  aliases without warning, so nothing else in the app hardcodes one.
- `src/state/chat.ts` buffers streaming text and flushes every 40 ms rather than
  re-rendering on every token.
- Images are downscaled to a 1300 px longest edge at pick time and encoded to
  base64 only when a message is sent, so neither the database nor memory holds
  megabytes of image data.
- `pickTextFile` in `src/lib/files.ts` asks the system picker for `*/*` and
  decides for itself what it can read. A MIME list passed to the picker is
  enforced by the OS rather than by this app, and it hides files this app reads
  fine: Android providers report code, markdown and log files as
  `application/octet-stream`, which is on none of the types that used to be
  listed, and iOS matches a listed type against its own declarations. The result
  is files that can be seen but not chosen, which reads as the attach button
  being broken. A read failure is also reported as such rather than as
  "not a text file", since the two need different fixes from the user.
- `Sheet` in `src/ui/components/Basic.tsx` is the app's only modal, and its
  layout is load-bearing. The anchor lays out flush to the bottom, so the
  keyboard spacer has to be the anchor's **last** child: placed first it only
  opens a gap above a card that never moves. The card carries `flexShrink: 1`
  so that as the spacer grows the card's height follows it, instead of a long
  system prompt pushing the card's own top off the screen. Editing either of
  those two facts re-breaks editing inside sheets on Android.

## Tools the model can call

Nothing runs on DeepSeek's side: the API relays call definitions and returns
calls, and every one of them is executed on the device. The guarantees are
therefore the app's to keep.

| Tool | Offered when | What it can reach |
| --- | --- | --- |
| `search_web` | Research is on, or the globe toggle is lit | A search provider (DuckDuckGo and Wikipedia need no key; Serper uses its own key, stored in the keychain like the DeepSeek one) |
| `create_folder` | Agent mode is on **and** a workspace folder is picked | That folder, and nothing else |
| `write_file` | Same as above | Same as above |

Agent mode is off by default and does nothing until you pick a folder. Paths
come from the model, so they are treated as hostile: `sanitizeRelativePath`
refuses anything absolute, anything containing `..`, URI schemes, control
characters, paths over 200 characters or deeper than 12 levels, and the write
is capped at 512 KB.

There is no file permission to grant on either platform — the picker itself
hands the app a grant for the folder you chose, and that grant is what turns
the tools on. Android keeps it across restarts (SAF); on iOS it is a
security-scoped bookmark that dies with the session, so the app asks you to
pick the folder again. The chat banner covers both cases, and also the one
where a stored folder stops answering because it was deleted or was on a card
that is no longer mounted.

`src/lib/workspace.ts` is worth reading before changing anything about folder
access. It resolves each level of a path against a **listing of the level
above** and uses the `Directory` and `File` objects the API handed back, rather
than constructing one by joining a name onto its parent. That is not a
preference: a SAF child is addressed by a document id the provider issued, and
a URI built by string concatenation satisfies neither `isTreeUri` nor
`isDocumentUri`, so it addresses nothing. The observable failure was every
folder and every file being re-created instead of reused, and Android's
`createDocument` renaming on collision, which left a project as
`app (1)/src (1)/main.ts (1)` rather than updating it.

Two test files cover that, and they are not interchangeable.
`workspace.saf.test.ts` replaces the whole `expo-file-system` module, so it
tests the app's own logic and nothing beneath it.
`workspace.bridge.test.ts` replaces only the native bridge, so the package's
real `Directory` and `File` classes, its `Paths.join`, and the
`listAsRecords`-to-object wrapping all run on top of a provider modelled
line-by-line on `SAFDocumentFile.kt` and AOSP's `DocumentsContract`. It fails
if the lookup ever goes back to joining URIs, and it pins the failure mode so
it cannot come back quietly.

The one write path the app does not trust is `File.write`. On Android it opens
with `if (!exists) { create() }`, and `exists` is `DocumentFile.isFile()`,
which reads the provider's `mime_type` column and answers *false* when the
provider does not report one — so the write lands in `create()`, which refuses
every `content://` URI outright. A provider that declines to answer a column
therefore makes a file it is holding itself look missing. `writeWorkspaceFile`
tries the ordinary write first and, only if it throws, opens a file handle and
writes the UTF-8 bytes through it: `openHandle` goes straight to
`contentResolver.openFileDescriptor(uri, "w")`, which asks nothing about
whether the document exists. A folder that works never reaches the second
attempt.

A turn is capped at four rounds of tool use, so a model that calls tools in a
loop cannot bill you for a loop you cannot see the end of. Stopping a turn
cancels the request in flight, the tool call in progress, and the rounds that
would have followed.

The HTML preview executes model output, which the chat renderer otherwise never
does. It is sandboxed: no file access, no DOM storage, no second windows, and
navigation away from the document is refused.

## DeepSeek API

Base URL `https://api.deepseek.com`, chat at `/chat/completions`, OpenAI-compatible.

- Thinking is `"thinking": {"type": "enabled"}` plus `"reasoning_effort"`, and
  arrives on `delta.reasoning_content` separately from `delta.content`.
- `temperature`, `presence_penalty`, and `frequency_penalty` are silently ignored
  by models with thinking mode. The settings screen says so rather than offering
  controls that do nothing.
- Vision accepts images as base64 data URLs, JPEG/PNG/GIF/WebP, up to 32 MiB each.
  Images are only sent to models whose registry entry has `vision: true`.
- Cost figures are estimates from published off-peak prices, doubled during peak
  hours (01:00–04:00 and 06:00–10:00 UTC, weekdays).

## Design rules

The interface is monochrome plus a single amber accent. There is no second hue:
errors, warnings, and destructive actions are carried by wording, weight, and
icons. No emoji anywhere in the UI or the source. Outlines are 1.5 px strokes;
surfaces are separated by hairline borders rather than shadows.
